# 기간별 학습 리포트 기능 스펙

## 확정 UX

- 일반 최초 진입은 전체, 각 덱 바로가기는 해당 덱 리포트로 진입한다.
- 상단은 전체 또는 덱 이름과 그 아래 실제 조회 날짜 범위만 표시한다.
- 이름 옆 아래쪽 꺾쇠를 누르면 검색 없는 ‘조회 조건’ 바텀시트를 연다.
- 시트에서 덱과 최근 7일·최근 30일·직접 설정 기간을 임시 선택한다. 덱 목록 첫 항목은 전체다.
- 상단 오른쪽 체크로 덱·기간을 함께 반영한다. 하단 적용 버튼은 없다. X·바깥 터치·뒤로 가기는 미적용 변경을 취소한다.
- 덱 목록만 스크롤하며 스크롤바는 표시하지 않는다. 기간·전체·상단 조작은 고정한다.
- 전체 누적은 전체 선택 때만 표시한다. 개별 덱에서는 선택 기간 통계와 카드별 평가 이력을 보여준다.

삭제 후 이력은 A안(평가 이력·통계 유지, 삭제된 덱 이름·카드 본문 숨김)으로 확정했다(담당자(RyuSw-cs)가 2026-10-20 Agent 대화에서 A안 확정). Planning 원본에는 아직 없어 Step4에서 반영한다. 아래 API 계약·서버 변경안은 구현 전 대조할 제안으로 구분하며, 이 스펙 저장이 제품 구현이나 정책 반영을 뜻하지 않는다.

## 목적과 상태

학습한 양과 스스로 내린 평가를 기간·덱·카드 단위로 확인한다. 기존 학습 직후 결과 화면에 없던 과거 기록 탐색을 추가한다. 기대 가치는 학습 습관을 돌아보고 어려웠던 카드를 찾는 부담을 줄이는 것이다. 암기 향상을 검증한 기능으로 표현하지 않는다.

- 이슈: https://github.com/whatever-x/Caro-Workflow/issues/12 (기존 Caro-Planning#6에서 2026-10-20 이전. 이후 진행·보드 추적은 Workflow#12)
- 담당자: `RyuSw-cs`. 개발 완료일: `2026-10-21`(Workflow#12 본문과 보드 ‘완료 예정일’ 기준. 이전 초안의 2026-10-20을 대체).
- 이번 종료점: Step3 설계. 제품 코드·마이그레이션·Planning 정책 변경·배포는 Step4 범위다.
- 상태: 화면 시안의 ui-styling 검토·개발 명세 정리 완료. 삭제 후 이력 처리는 2026-10-20 A안으로 확정했다. 2026-10-20 Figma MCP로 기존 화면을 대조하고 진입점·평가 색을 Figma 기준으로 정정했다. 리포트 화면 자체는 Figma에 없어 Step4 첫 작업으로 만든다(아래 ‘Figma 대조’).
- 정본: 이 문서. 서버 상세: [Caro-Backend API 설계](https://github.com/whatever-x/Caro-Backend/blob/chore/learning-report-spec/src/main/kotlin/com/whatever/caro/study/docs/2026-10-16-learning-report-api.md).

### 회의 입력과 채택 범위

별도 회의록은 없다. 사용자는 이 Agent 대화를 회의록으로 취급하라고 지정했다. ‘차트나 진행도’, 전체 기록, 모든 덱 합계와 개별 덱, 카드별 평가 표시를 요청했다. 최근 7일·최근 30일·직접 설정, 일일 학습 집계, 평가 횟수와 고유 카드 수 구분, 누적 기록, 카드별 평가 이력을 권고한 뒤 ‘확인. 다음 단계 진행’으로 Step3 진행을 요청했다. 아래 세부 계약은 그 범위의 설계 제안이다. 삭제 이력처럼 이전 답변에서 미확정으로 남긴 정책을 포괄 승인으로 취급하지 않는다.

후속 확정: 리포트 상단에는 선택한 덱 이름과 그 아래 적용된 날짜 범위만 표시한다. 이름 바로 옆 작은 아래쪽 꺾쇠로 덱·기간을 함께 설정하는 조회 조건 바텀시트를 연다. 화면의 간결함을 우선하며 기간 칩은 본문에서 제거한다. 스크롤바 표시는 삭제하고 목록 스크롤과 추가 로딩은 유지한다. 목록 첫 항목은 ‘전체’, 일반 최초 진입도 ‘전체’다. 전체 누적은 전체 선택 때만 표시한다. 각 덱에서 해당 덱 리포트로 바로 진입한다. 직접 진입에 deckId가 있으면 해당 덱으로 열고, 일반 진입은 이전 선택을 저장해 자동 복원하지 않는 것으로 해석해 전달했다.

- Backend `study/internal/studysession/{ReviewLog,StudySession,ReviewLogRepository,StudySessionRepository}.kt`: 평가·cardId·userId·세션·시각·학습일 저장. 카드 본문 스냅샷은 없다.
- Backend `study/internal/EvaluationService.kt`: 유효한 평가만 로그로 저장하며 완료 전 평가도 남는다. 동일 세션의 재평가는 제외한다.
- Backend `study/internal/streak/StudyDayRepository.kt`: 사용자 단위 휴식 기록. 덱별 과거 휴식을 복원할 자료는 없다.
- Backend `study/internal/web/StudyController.kt`: 기존은 특정 덱의 오늘 요약. 기간별 리포트 API는 신규 제안이다.
- Backend `card/api/{card/CardApi,deck/DeckApi}.kt`, `card/internal/card/CardService.kt`: 현재 카드 내용은 소유자·활성 카드로 한정해 일괄 조회. 과거 카드 본문을 복원한다고 약속하지 않는다.
- Backend `study/AGENTS.md`, `bff/AGENTS.md`, `common/AGENTS.md`: 모듈 API를 통한 조합, 인증과 기존 오류·버전 규약을 따른다.
- Backend `card/internal/card/CardService.deleteCard`: 카드·노트 soft delete와 `CardsDeletedEvent`. `card/internal/deck/service/DeckService.deleteDeck`: 덱만 soft delete하고 `DeckDeletedEvent`를 받는 listener가 없다(`card/AGENTS.md`). 즉 삭제 덱의 카드는 `deletedAt`이 null인 채 남고, `ReviewLog`·`StudySession`을 지우는 일반 삭제 경로는 없다. 유지안은 저장 변경 없이 가능하다.
- Figma MCP는 2026-10-20 연결 후 읽기만 했다. Slack MCP 연결 도구는 없다(2026-10-20 재확인). 이 이슈에는 Slack 스레드도 연결돼 있지 않다. 연결된 논의를 모두 읽었다고 보고하지 않는다.

## 범위와 대안

채택안은 조회 중심이다. 기존 로그를 집계하고 현재 카드 내용을 붙인다. 카드 본문의 과거 버전을 저장하는 안은 신규 저장·마이그레이션이 필요하므로 제외한다. 차트 없이 기존 오늘 진행도만 확대하는 안은 과거 변화와 카드별 탐색을 충족하지 못하므로 채택하지 않는다.

포함: 기간 선택, 모든 덱/개별 덱, 평가 횟수·고유 카드 수·학습일 수, 일별/주별/월별 학습량 차트, 평가 분포, 누적 요약, 기록 목록, 카드별 평가 이력과 평가별 필터.

제외: 벼락치기 기록 저장, 정확한 정답률·암기율, 숙달도 공식, 학습시간 통계, 미래 복습 예측, 기간 비교, 내보내기, AI 분석, 새 하단 탭, 기존 학습 순서·streak 계산 변경. 기존 홈/덱의 오늘 진행도는 유지한다. 이번 리포트의 차트로 ‘차트나 진행도’ 요구를 충족하며 기간 목표 달성률은 만들지 않는다.

## 사용자 흐름과 이미지 시안

사용자가 확인한 이름 옆 꺾쇠와 검색 없는 덱·기간 통합 조회 조건 바텀시트를 개발 기준으로 정리했다. 실제 앱 screenshot이나 Figma에 확정된 디자인은 아니며 모든 수치는 예시다. 9·10번 진입 화면은 Figma 기존 화면 구조를 따르고 추가 요소만 노란 테두리로 표시했다. PNG는 화면 구조·위계·상태의 기준이고 실제 치수·상호작용은 아래 개발 명세와 앱 토큰을 따른다.

- [긴 목록·조회 실패·320 폭](assets/learning-report-development.png): 검색 없는 시트의 고정/스크롤 구분과 좁은 화면·확대 글자 레이아웃 예시.
- [조회 조건 단일 시안](assets/learning-report-selector.png): 간결한 리포트와 덱·기간 통합 시트의 닫힘/열림 상태.
- [주요 흐름](assets/learning-report-flow.png): 전체 리포트, 덱 리포트, 학습 기록 목록, 카드별 평가 이력.
- [기간·빈 상태·오류](assets/learning-report-states.png): 시트 내부 날짜 직접 설정, 선택 기간 기록 없음, 조회 실패와 재시도.
- [덱 선택과 바로가기](assets/learning-report-selection.png): ‘전체’가 첫 번째인 덱 선택, 홈 덱별 바로가기와 덱 상세 진입.

1. 홈 파란 헤더의 연속 학습 칩 옆에 ‘학습 리포트 ›’ 칩을 둔다(전체 리포트). 덱이 없어도 기존 이력이 있으면 접근할 수 있다. 홈의 각 덱 아이템은 기존 구성(이름·상태 배지·설명·진행 바·카드 수·학습 버튼)을 유지하고 하단 구분선 아래 ‘학습 리포트 ›’ 행을 더한다. 덱 상세는 ‘하루 학습’ 영역의 ‘N개 카드 · %’ 오른쪽에 ‘학습 리포트 ›’를 둔다. 세 진입점 모두 Figma의 Button - Small(텍스트+ic_arrow_right 16) 형태, text.secondary 색이며 터치 영역은 Android 48dp·iOS 44pt 이상이다. 일일학습·벼락치기 버튼 구성과 카드 목록은 바꾸지 않는다.
2. 일반 리포트 진입은 ‘전체’·최근 7일이다. 이전 덱 선택을 기본값으로 저장하지 않는다. 덱 바로가기는 해당 deckId·최근 7일로 직접 진입한다. 카드를 모두 삭제한 덱에서도 덱 상세의 진입점을 유지한다. 같은 리포트 탐색에서 뒤로 돌아올 때는 기존 필터 상태를 유지한다.
3. 상단에는 ‘전체’ 또는 덱 이름과 이름 뒤 8dp 간격의 아래쪽 꺾쇠를 표시하고 그 아래에는 적용된 날짜 범위만 표시한다. 리포트 본문에 최근 7일·최근 30일·직접 설정 칩은 두지 않는다. `ic_arrow_down_16`은 text.secondary로 tint하고 이름+아이콘을 한 버튼으로 묶는다. 접근성 라벨은 ‘조회 조건 변경, 현재 {덱 이름 또는 전체}, {적용 날짜 범위}’, 버튼 역할과 열림 상태를 제공한다. 아이콘 자체는 중복 읽지 않는다. Android 48dp·iOS 44pt 이상 터치 영역을 확보한다. 누르면 ‘조회 조건’ 바텀시트를 열고 기간·덱을 임시 선택한다. 상단 취소(X)·제목·완료 체크, 기간 칩과 임시 날짜, 덱 제목·첫 항목 전체는 고정하고 덱 목록만 스크롤한다. 스크롤바·검색창은 표시하지 않는다. 덱·기간을 골라도 닫거나 리포트를 갱신하지 않는다. 하단 ‘적용’ 버튼은 두지 않는다. 상단 오른쪽 체크 아이콘을 눌러 둘을 한 번에 반영한다. 체크의 접근성 이름은 ‘조회 조건 적용’이며 Android 48dp·iOS 44pt 이상 터치 영역을 확보한다. 상단 왼쪽 X는 ‘조회 조건 취소’다. ‘취소’·바깥 터치·메인 시트에서 뒤로 가기는 모든 미적용 변경을 버리고 기존 조회를 유지한다. 긴 이름은 꺾쇠를 포함한 컨트롤 안에서 줄바꿈하며 아이콘을 화면 오른쪽 끝으로 밀지 않는다. 최근 7일은 오늘 포함 `today-6..today`, 30일은 `today-29..today`다.
4. ‘전체 누적’은 ‘전체’를 선택했을 때만 표시한다. 개별 덱에서는 누적 영역과 그 자리 여백을 모두 제거하고 선택 기간 통계부터 표시한다. 전체 누적은 기간 변경과 무관하다. 전체로 변경해 적용하면 다시 조회·표시한다.
5. 선택 기간에는 평가 횟수·학습한 카드·학습일, 학습량 차트와 3종 평가 분포를 표시한다. 빈 날짜도 차트에 0으로 포함한다.
6. ‘학습 기록 보기’는 선택한 덱·기간의 세션별 목록이다. ‘전체 기간 보기’를 누르면 기간만 전체로 바꾸고 덱 선택은 유지한다. 날짜/덱/평가 횟수/평가 분포를 표시한다.
7. 덱 리포트의 ‘카드별 평가’는 선택 기간에 평가한 고유 카드 목록이다. 최근 평가·기간 내 평가 횟수·마지막 평가일, 현재 앞면/뒷면 미리보기를 표시한다. 평가 필터는 ‘기간 내 마지막 평가’를 기준으로 한다.
8. 카드 선택 시 같은 덱·기간의 날짜별 평가 이력을 펼친다. 전체 기간 보기로 그 카드의 전체 이력을 볼 수 있다. 기존 카드 편집·삭제 화면의 기능은 복제하지 않는다.
9. 뒤로 가기는 기간·덱·평가 필터·목록 위치를 보존한다. 덱 또는 기간 변경 시 오래된 응답은 폐기하며 이전 필터의 수치를 새 필터 아래에 표시하지 않는다.

### 덱 선택 컨트롤의 디자인 원칙

선택의 의미를 형태로 전달한다. 이름 옆 아래쪽 꺾쇠는 다른 조회 범위가 있음을 나타내며, 이름 편집을 연상시키는 연필은 사용하지 않는다. 시트가 열리면 꺾쇠를 위로 돌린다.

기존 파란색 헤더와 Pretendard·배경 토큰을 유지한다. 현재 선택 이름이 시각적 기준이며 아이콘은 16dp 보조 요소다. 별도 채움 버튼이나 멀리 떨어진 조작 요소를 만들지 않는다.

이름과 꺾쇠를 하나의 넓은 터치 영역으로 묶는다. 현재 값과 열림 상태를 스크린 리더에 제공하고 닫으면 트리거로 초점을 돌린다. 큰 글자·긴 이름에서도 컨트롤을 잘라내지 않는다.

조회 조건 시트는 덱 단일 선택과 기간 단일 선택을 한 번에 적용한다. 배경은 scrim으로 구분하고 임시 선택 항목은 텍스트·체크·밑줄로 알린다. 첫 항목 전체는 로딩과 무관하게 선택 가능하다. 같은 조건으로 적용하면 닫기만 하며 불필요한 재조회를 하지 않는다.

적용 근거: 사용자가 지정한 ui-styling의 선택 컨트롤·접근성·Canvas 지침. UI/UX 검색의 `caret-down`(dropdown/select) 의미를 확인했고 새 아이콘 라이브러리 대신 기존 앱의 벡터를 사용한다. PNG 시안이며 실제 터치·포커스 동작 검증은 구현 후 수행한다.

이번에 수행한 것은 시안 렌더·정적 대비 계산·문서/이미지 검사와 시각 검토다. 320 폭 이미지는 레이아웃 예시이며 실제 Android/iOS 실행, 시스템 최대 글자 크기, 가로 모드·다크 모드·스크린 리더 동작을 테스트했다고 주장하지 않는다. 해당 항목은 AC12의 구현 후 검증으로 남긴다.

### 조회 조건 상태와 완료 규칙

- 시트를 열 때 `draftFilter`를 `appliedFilter`에서 복사한다. 본문 제목·날짜·누적 표시와 API 요청은 applied만 사용한다.
- 덱 선택·기간 프리셋 변경은 draft만 갱신한다. 덱 목록의 추가 페이지 조회는 허용하되 리포트 집계 API는 호출하지 않는다.
- 직접 날짜 선택은 하위 편집 상태에서 진행한다. 완료하면 유효한 날짜 쌍을 draft에 넣고 메인 조회 조건 시트로 돌아간다. 뒤로 가면 그 날짜 편집만 취소한다.
- 상단 완료 체크는 유효한 덱·기간 쌍이 있을 때만 누를 수 있다. 유효하지 않으면 disabled 의미·색을 제공한다. 둘 중 하나라도 바뀌었으면 applied를 함께 바꾸고 기존 페이지 cursor를 초기화한다. 같은 조건이면 닫기만 한다.
- 메인 시트 X 취소·바깥 터치·뒤로 가기는 draft를 버린다. 다시 열면 마지막 적용값부터 시작한다. 리포트의 이전 스크롤·내용은 유지한다.
- API 계약의 메서드·필드·인증은 그대로다. 날짜·deckId를 요청하는 시점만 최종 적용 이후로 제한한다.

### 직접 설정과 긴 기간

직접 설정을 누르면 같은 시트의 내용을 날짜 선택 화면으로 전환한다. 모달을 겹쳐 띄우지 않는다. ‘기간 선택 완료’는 임시 날짜만 확정하고 조회 조건 시트로 돌아간다. 이 버튼만으로 리포트를 조회하지 않는다. 날짜 화면의 ‘뒤로’는 그 화면에서 바꾼 날짜를 버리고 기존 draft를 유지한다. 최종 반영은 메인 시트 상단 오른쪽 완료 체크에서만 한다. 시작일·종료일 모두 포함하며 하루만 선택 가능하다. 미래 날짜·역전 범위·한쪽만 입력은 적용 불가다. 조회 조건 시트 취소는 적용 전 덱과 기간을 모두 유지한다. 전체 기간은 첫 저장된 평가 학습일부터 오늘까지이며 기록이 전혀 없으면 시작일은 null이다. 첫 기록보다 이른 날짜를 직접 고르는 것은 허용하되 그 구간은 0이다.

차트 단위는 31일 이하 일, 32~180일 주, 181일 이상 월로 한다. 주는 선택 시작일부터 7일씩, 월은 달력 월로 나누며 첫·마지막 구간은 실제 선택 범위로 잘라 라벨을 표시한다. 이 값은 그래프 가독성을 위한 설계값이며 제품 기간 상한이 아니다. 길이가 큰 범위를 클라이언트에서 모든 원시 평가 로그로 집계하지 않는다.

## 집계와 데이터 의미

- 대상은 현재 사용자 소유의 DAILY 세션과 유효한 `ReviewLog`다. 세션 완료 여부로 평가 로그를 제외하지 않는다. `FULL_DECK`은 제외한다.
- 기간 판정과 차트 날짜는 저장된 `StudySession.sessionDate`로 통일한다. 서버 UTC 날짜나 기기 현재 시간대로 과거 학습일을 재분류하지 않는다. 화면은 ‘학습일 기준’으로 안내한다. 카드 상세의 실제 평가 시각은 저장된 세션 timezone으로 표시하고 timezone을 보조 정보로 제공한다.
- `reviewCount = COUNT(log)`, `uniqueCardCount = COUNT(DISTINCT cardId)`, `studyDayCount = COUNT(DISTINCT sessionDate)`(평가가 1개 이상인 날). 같은 카드 1장을 3일 평가하면 3회/1장/3일이다. 누적 학습일은 일일 학습을 완료한 날을 세는 streak 수치와 다르다.
- EASY/FAIR/AGAIN은 각각 쉬워요/애매해요/모르겠어요. 분포는 평가 횟수 기준이며 세 합계가 reviewCount와 같아야 한다. 0회면 비율은 0으로 처리하고 그래프에 가짜 비중을 만들지 않는다.
- 일별 고유 카드 수를 더해 기간 고유 카드 수로 사용하지 않는다. 고유 카드 수는 전체 선택 범위에서 다시 구한다.
- 누적 요약은 모든 덱·전체 기간 값으로 ‘전체’ 선택 때만 요청·표시한다. 개별 덱 응답은 lifetime을 생략하며 FE가 이전 전체 누적을 재사용하지 않는다. 기간 요약은 현재 선택한 덱 범위다. 모든 덱 합계의 고유 카드 수·학습일도 전체 범위에서 distinct로 계산한다.
- 카드의 최근 평가는 선택 범위에서 마지막 `(createdAt, id)`다. 리스트는 마지막 평가일시 내림차순, 동률은 cardId 내림차순이다. 카드 상세 이력은 `(createdAt, id)` 내림차순이다.
- 기록 목록은 세션별로 저장된 평가를 묶으며 `(sessionDate, sessionId)` 내림차순이다. 세션의 누적 카운터보다 로그 집계를 표시 기준으로 사용한다.
- 현재 카드 내용만 제공한다. 수정 시 ‘현재 카드 내용’임을 표시한다. 평가 당시의 본문·덱 이름은 복원하지 않는다.
- 계정 탈퇴 시 기존 인증 차단·개인정보 파기 규칙을 유지한다. 리포트용 별도 영구 보관소를 만들지 않는다.

## 신규 API 계약

모두 **신규 제안**, GET, `API-Version: 1.0`, `Authorization: Bearer <access token>`, `Client-Timezone: <IANA ZoneId>`를 사용한다. 기존 API의 기본 버전·필드는 바꾸지 않는다. 응답은 기존 `ApiResponse<T>`다. `Accept-Language`는 기존 오류 지역화에 사용한다.

### 공통 입력·타입

`deckId?: int64` 생략 시 모든 덱, 지정 시 소유권 확인. `startDate?: YYYY-MM-DD`, `endDate?: YYYY-MM-DD` 둘 다 생략하면 전체 기간, 한쪽만 지정은 400. 최근 7/30일은 FE가 명시 날짜 쌍으로 보낸다. 서버는 `Clock`과 `Client-Timezone`으로 오늘을 검증한다. 미래일/역전/유효하지 않은 날짜는 400. 역사적 집계는 저장 학습일 기준이다.

페이지 목록은 `limit?: int32=20`(1~100), `cursor?: string`을 사용한다. 페이지 응답은 `{items: T[], nextCursor: string|null}`. 각 항목 필드는 아래에서 nullable로 표시한 것 외에는 필수다. int64 수치는 FE `Long`으로 받는다. 날짜는 ISO LocalDate, 시각은 ISO-8601 Instant, 문자열은 Unicode다.

| 경로 | 추가 입력 | `data` 필드 |
|---|---|---|
| `/study-reports/summary` | 공통 범위 | `scope: Scope`, `range: Range`, `lifetime?: Counts`, `selected: Counts`, `buckets: Bucket[]`, `restDates: LocalDate[]` |
| `/study-reports/decks` | `limit,cursor` | `Page<DeckOption>`: 현재 소유 덱과 이력이 있는 삭제 덱 후보. 사용자 소유 증거 없는 항목 제외. |
| `/study-reports/sessions` | 공통 범위, `limit,cursor` | `Page<SessionRecord>` |
| `/study-reports/cards` | `deckId` 필수, 날짜 쌍, `lastRating?: EASY|FAIR|AGAIN`, `limit,cursor` | `Page<CardRecord>` |
| `/study-reports/cards/{cardId}/reviews` | `deckId` 필수, 날짜 쌍, `limit,cursor` | `card: CardLabel`, `range: Range`, `items: ReviewRecord[]`, `nextCursor: string|null` |

| 타입 | 필드와 의미 |
|---|---|
| `Scope` | `deckId: int64|null`, `deckName: string|null`, `deleted: boolean`. 전체 선택은 null/null/false. 삭제 덱 이름은 null. |
| `Range` | `startDate: LocalDate|null`, `endDate: LocalDate`, `bucketUnit: DAY|WEEK|MONTH`. 전체 기간·기록 없음에서만 시작일 null. |
| `Counts` | `reviewCount, uniqueCardCount, studyDayCount: int64`, `ratings: {easy,fair,again:int64}`. 음수 불가. |
| `Bucket` | `startDate,endDate: LocalDate`, `reviewCount:int64`, `ratings:{easy,fair,again:int64}`. 선택 범위를 빈칸 없이 덮고 빈 구간도 반환. |
| `DeckOption` | `deckId:int64`, `name:string|null`, `deleted:boolean`. 정렬은 deckId 내림차순. 이름 검색은 첫 범위에서 제외. FE가 첫 항목 ‘전체’(deckId=null)를 고정 삽입하며 서버는 가짜 덱 항목을 만들지 않는다. 페이지 로딩·오류·빈 덱 목록에서도 ‘전체’는 선택할 수 있다. |
| `SessionRecord` | `sessionId,deckId:int64`, `deckName:string|null`, `deckDeleted:boolean`, `studyDate:LocalDate`, `timezone:string`, `status:ACTIVE|COMPLETED|STOPPED`, `counts:Counts`. history counts.studyDayCount는 평가 있으면 1. |
| `CardLabel` | `cardId:int64`, `deleted:boolean`, `front,back:string|null`. 활성 카드는 현재 내용, 삭제 카드와 삭제 덱에 속한 카드는 `deleted=true`, 둘 다 null. |

`lifetime`은 deckId 생략 시에만 필수이며 지정 시 응답에서 생략한다. 개별 덱의 누적 집계는 실행하지 않는다.

`restDates`는 모든 덱 범위일 때 실제 저장된 사용자 REST_DAY 중 평가가 없는 선택 범위 날짜만 반환한다. 덱별·주/월 차트에서는 빈 배열로 반환한다. ‘학습 안 함’과 ‘휴식’을 임의 추론하지 않는다.

### 인증·오류·페이지 일관성

- userId 입력은 받지 않고 현재 인증 사용자에서 얻는다. 로그와 세션 모두 그 사용자로 제한한다. 카드 본문도 CardApi의 사용자 제한 조회만 사용한다.
- 특정 덱은 현재 소유 덱이거나 본인 세션으로 소유 증거가 확인된 삭제 덱일 때만 접근한다. 없는/타인 덱과 카드 이력은 404 제안으로 통일하고 존재 여부를 노출하지 않는다. 기존 덱 API의 403/404 계약은 바꾸지 않는다.
- 400: 날짜/필터/limit/cursor/시간대 형식 오류. 401: 인증 만료·미인증. 404: 접근 가능한 대상 없음. 5xx/네트워크 오류: 해당 영역 재시도. 정확한 신규 오류 번호는 Step4에서 당시 `StudyErrorCode`의 최대 번호 다음으로 배정하고 중복 검사한다.
- 평가 기반 목록의 keyset cursor에는 마지막 정렬 키와 최초 페이지의 최대 reviewId, 덱·기간·평가 필터 식별자를 담는다. 덱 선택 목록은 deckId 순 cursor와 최초 최대 deckId를 사용한다. userId는 인증값만 신뢰한다. 필터 불일치/잘못된 형식은 400. 위조된 cursor로도 사용자 조건을 벗어난 조회를 할 수 없어야 한다.
- 같은 목록 탐색에서는 최초 페이지까지의 로그만 조회해 새 평가 추가로 페이지가 밀리지 않게 한다. 필터 변경/새로고침은 새 탐색이다. 여러 API 호출을 원자적 스냅샷으로 보장하지 않으며 최신 학습 직후에는 새로고침한다.
- 조회만 수행한다. GET에 `Idempotency-Key`·평가 로그 생성·streak 동기화·별도 집계 저장을 추가하지 않는다. 대량 원시 로그 전송이나 카드별 반복 API 호출도 하지 않는다.

## 다른 컴퓨터에서 이어가기

각 원본 저장소를 clone한 뒤 해당 저장소 루트에서 실행한다. 이미 브랜치가 있으면 `git switch <브랜치>`로 전환한다.

```sh
# Caro-Mobile
git fetch origin
git switch --track origin/docs/learning-report-spec
```

```sh
# Caro-Backend
git fetch origin
git switch --track origin/chore/learning-report-spec
```

스펙의 상대 이미지 링크는 같은 브랜치의 시안을 가리킨다. 구현을 시작하기 전 최신 develop, Step4에서 만든 리포트 Figma와 반영한 Planning 정책을 다시 대조한다.
