# 브랜치·커밋·PR 작업 지침

브랜치를 만들거나 커밋·PR 작업을 수행할 때 읽습니다. 공통 작업 절차는 루트 [AGENTS.md](../../AGENTS.md)를 따릅니다.

## 브랜치

브랜치 생성 전에 현재 브랜치와 작업 트리를 확인합니다. 기준 브랜치로 전환할 때 기존 변경사항을 잃지 않도록 합니다.

| 구분 | 기준·이름 |
| --- | --- |
| `main` | 실제 프로덕트 코드를 관리하는 고정 브랜치 |
| `develop` | 다음 출시를 위한 기능 개발이 완료된 고정 브랜치 |
| 기능 개발 | `develop`에서 생성. `feat/`, `refactor/`, `fix/`, `init/`, `chore/`, `build/`, `docs/` 사용 |
| 릴리스 준비 | `develop`에서 `release/` 생성 |
| QA | 해당 `release`에서 `qa/` 생성 |
| 핫픽스 | `main`에서 `hotfix/` 생성 |

릴리스 브랜치는 플랫폼별로 나누지 않고 하나로 관리합니다.

- Android만 출시: `release/android-x.x.x`
- Android·iOS 함께 출시: `release/android-x.x.x-ios-x.x.x`
- 릴리스 중 대상 플랫폼이 추가되면 이름 변경으로 반영합니다. 예: `release/android-1.0.1` → `release/android-1.0.1-ios-1.0.1`

## 커밋

`type: 작업 내용` 형식으로 작성합니다. 예: `feat: 메모 MVI 작성`.

| 타입 | 적용 기준 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `init` | Composable·Activity·ViewModel 등 초기 파일 생성 |
| `fix` | develop에 있던 기능 수정 |
| `chore` | 버전 코드·패키지 구조·파일 이동·이름·가독성·포맷 변경 |
| `refactor` | 내부 동작을 유지하면서 기존 코드 개선 |
| `build` | 버전 카탈로그·build-logic·Gradle·의존성 변경 |
| `docs` | README·지침서 등의 문서 개정 |
| `hotfix` | 핫픽스 브랜치에서 수행하는 수정 |

## PR 제목과 본문

제목은 작업 내용을 한 줄로 요약하고 아래 키워드를 반드시 붙입니다.

| 키워드 | 작업 성격 |
| --- | --- |
| `[Init]` | 초기화 |
| `[Feature]` | 기능·함수·클래스·변수 추가 |
| `[Refactor]` | 코드 최적화·기능 개선 |
| `[Build]` | 빌드 |
| `[Docs]` | 문서 |
| `[Chore]` | 패키지·경로·모듈·함수·클래스·변수 이름 변경 |
| `[Fix]` | 버그 수정 |
| `[Hot Fix]` | 치명적인 버그의 긴급 수정 |
| `[Release]` | 프로덕션 배포 준비 |
| `[QA]` | QA 피드백 반영 |

본문은 [PR 템플릿](../../.github/pull_request_template.md)을 따릅니다.

- 관련 이슈: 이슈 번호를 연결합니다. 종료할 이슈에는 `Closes #번호`를 사용합니다.
- 작업한 내용: 변경 결과를 요약합니다.
- PR 포인트: 고민 사항·건의·요청과 리뷰 시 확인할 지점을 적습니다.

## PR 생성 시 확인할 정책

PR 생성 전에 아래 목록에서 적용할 정책을 읽고, 각 정책에 지정된 시점에 수행합니다. 새로운 PR 정책은 이 목록에 등록하고 [문서 탐색 목록](../index.md)의 연결을 갱신합니다.

| 정책 | 적용 조건·시점 | 읽을 문서 |
| --- | --- | --- |
| PR 스크린샷 | PR 생성 작업에 적용. 생성 후 실제 diff·시나리오를 확인하고 실행 전 판단·승인 절차 수행 | [PR 스크린샷 정책](../../.agents/hooks/pr-screenshot/pr-screenshot.md#사용자-확인-기준) |

훅 등록 여부와 관계없이 정책을 적용합니다. PR 생성 승인 자체는 스크린샷 실행 승인이 아닙니다. 판단 기준·승인·SHA 고정·실행 절차는 정책 원본에서 관리합니다.
