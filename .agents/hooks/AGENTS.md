# 에이전트 훅 관리 지침

`.agents/hooks/`의 훅을 설치·운영하거나 패키지와 관련 문서를 작성·수정할 때 적용합니다.

## 훅 설치 방법

1. [훅 탐색 목록](index.md)에서 필요한 훅을 찾고 해당 패키지의 사용 지침을 읽습니다.
2. 선택한 패키지의 설정 레퍼런스를 읽습니다.
3. 사용 중인 에이전트의 공식 지침에서 지원 조건·등록 위치·이벤트·입출력 형식·활성화 방법을 확인합니다.
4. 패키지에서 요구하는 도구와 의존성을 확인합니다. 여러 훅을 설치할 때는 이벤트·감지 조건의 중복과 충돌을 확인합니다.
5. 요청받은 범위에서 필요한 설정을 프로젝트 로컬 또는 사용자 영역에 등록합니다.
6. 공식 지침에 따라 활성화하고 실제 세션에서 로딩 여부를 확인합니다.
7. 공유 원본이 변경되면 등록본을 갱신하고 활성화 상태를 다시 확인합니다.

개발자별 로컬 설정·등록본은 Git 공유 대상에서 제외합니다.

## 훅 동작과 후속 작업

1. 설치·활성화된 훅은 사용 중인 에이전트가 등록된 이벤트에 따라 자동으로 호출합니다.
2. 훅은 이벤트 입력의 감지 조건을 확인하고, 조건에 맞으면 설정된 처리를 수행합니다.
3. 에이전트에게 후속 안내가 전달되면 해당 패키지의 사용 지침을 읽고 필요한 작업을 수행합니다. 설정·동작·검사 상세는 필요한 레퍼런스에서 확인합니다.
4. 후속 작업은 사용자 요청과 해당 정책의 승인 범위에서 수행합니다. 훅 실행 여부와 후속 작업 결과를 구분해 확인합니다.

설치된 훅을 작업마다 다시 선택하거나 수동으로 호출하는 절차는 두지 않습니다.

## 훅 작성 규칙

- 훅 원본과 관련 파일은 `<hook-name>/` 패키지에서 관리합니다. 이름에는 영문 소문자·숫자·하이픈을 사용합니다.
- 설정 원본은 `<hook-name>.json`, 사용 지침은 `<hook-name>.md`로 구분합니다.
- 설정 원본에는 목적·이벤트·감지 조건·실행 내용과 필요한 실행 제한을 명시합니다. 등록 시 사용할 설정 형식은 대상 에이전트의 지원 사양과 대조합니다.
- 사용 지침에는 적용 조건·핵심 작업 절차·승인과 실행 범위·결과 확인 방법을 작성합니다.
- 상세 설정·입출력·감지 범위·검사는 `references/`에서 관리합니다. 사용 지침에서 읽을 조건과 상대 링크를 명시합니다.
- 사람을 위한 소개는 `README.md`에 둡니다. 에이전트 작업 규칙은 이 지침과 패키지의 사용 지침에서 관리합니다.
- 패키지를 추가·이동·삭제하거나 이름을 변경하면 [훅 탐색 목록](index.md)과 관련 링크·상위 지침·훅 후속 안내·검사 경로를 갱신합니다.
- 변경 후 설정 JSON·링크·앵커와 해당 패키지의 오프라인 검사를 확인합니다. `git diff --check`를 실행합니다.

아래는 현재 패키지 구성을 바탕으로 한 구조 예시입니다.
레퍼런스는 필요한 경우에만 둡니다.

```text
hooks/
├── AGENTS.md                         # 훅 관리 지침
├── index.md                          # 설치·설정 관리용 훅 탐색 목록
├── README.md                         # 사람을 위한 소개
└── <hook-name>/
    ├── <hook-name>.json               # 훅 설정 원본
    ├── <hook-name>.md                 # 적용 조건·핵심 작업 절차
    └── references/                   # 선택: 상세 설정·동작·검사
        ├── <hook-name>-setup.md
        └── <hook-name>-runtime.md
```

## 가드레일

- 저장소에 파일이 있다는 이유로 훅이 등록·활성화되었다고 가정하지 않습니다.
- 등록된 이벤트·감지 조건을 확인하지 않고 모든 작업이나 대화에서 훅이 실행된다고 가정하지 않습니다.
- 지원 여부나 입출력 호환성을 확인하지 못하면 등록을 진행하지 않습니다.
- 공유 원본을 에이전트별 설정 디렉토리로 이동하지 않습니다. 필요한 설정만 복사·등록합니다.
- 기존 설정을 임의로 덮어쓰거나 같은 훅을 중복 등록하지 않습니다.
- 개인 설정·자격증명은 공유 원본이나 설치·배포 패키지에 포함하지 않습니다.
- 사용자 승인이 필요한 작업에서 훅의 실행 안내나 사용자의 미응답을 승인으로 처리하지 않습니다.
- 훅이 없거나 감지하지 못했다는 이유로 해당 패키지의 작업 정책을 생략하지 않습니다.
- 경로 정리 작업에서 감지 조건·사용자 승인 정책·CI 동작을 변경하지 않습니다.
- 별도 실행 스크립트가 필요하지 않으면 추가하지 않습니다.
- 오프라인 검사 통과를 실제 세션의 활성화나 CI 실행 성공으로 보고하지 않습니다.
