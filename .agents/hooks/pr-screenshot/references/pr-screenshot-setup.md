# PR 스크린샷 훅 설정 레퍼런스

훅 최초 등록·활성화·등록본 갱신·설정 진단 시 읽습니다. 판단·승인 규칙은 [본문](../pr-screenshot.md#사용자-확인-기준)을 따릅니다.

## 사용 중인 에이전트의 공식 지침 확인

사용 중인 에이전트의 공식 훅 설정 지침에서 다음 항목을 확인합니다. 도구별 설정 경로나 명령을 다른 에이전트에 그대로 적용하지 않습니다.

| 확인 항목 | 확인할 내용 |
| --- | --- |
| 지원 조건 | 현재 버전·실행 환경에서 도구 실행 후 훅을 지원하는지 확인 |
| 등록 위치·범위 | 프로젝트 로컬·사용자 영역 등록 위치, 다른 프로젝트에 미치는 범위, 기존 설정 병합 방법 확인 |
| 이벤트·도구 매핑 | 원본의 `PostToolUse`와 `Bash`에 해당하는 이벤트·도구 이름 확인 |
| 입력·출력 형식 | 원본 명령에 전달하는 JSON과 `hookSpecificOutput.additionalContext` 반환 형식의 호환성 확인 |
| 활성화·신뢰 | 훅 로딩 확인, 신뢰 검토, 비활성화 정책, 설정 반영·세션 재시작 조건 확인 |
| 프로젝트 지침 로딩 | 루트 AGENTS.md와 본문을 읽는 방법 확인. 자동 로딩이 없으면 직접 읽음 |

공식 문서는 에이전트가 제공하는 문서 검색·도움말 또는 공식 사이트에서 찾습니다. 설정 경로나 지원 버전을 추측하지 않습니다. 호환성을 확인할 수 없거나 훅을 지원하지 않으면 등록을 진행하지 않습니다. [판단·승인 절차](../pr-screenshot.md#사용자-확인-기준)는 직접 수행합니다.

## 공통 등록 절차

1. 프로젝트 루트에서 `jq --version`으로 실행 가능 여부를 확인합니다.
2. [원본 JSON](../pr-screenshot.json)과 [동작 계약](pr-screenshot-runtime.md#입력과-출력)을 확인합니다.
3. 공식 지침에서 입력·출력·이벤트 호환성을 확인합니다. 현재 원본을 모든 에이전트가 지원한다고 가정하지 않습니다.
4. 설정 작업을 요청받은 범위에서 원본의 `hooks` 항목을 에이전트의 프로젝트 로컬 또는 사용자 영역에 등록합니다. 기존 설정을 보존하고 중복 항목을 만들지 않습니다.
5. 원본의 `description`은 배포용 설명이므로 도구 설정에 복사하지 않습니다. 이벤트·matcher·명령·timeout은 함께 등록합니다.
6. 공식 지침에 따라 신뢰 검토와 활성화를 완료합니다. 실제 세션에서 해당 훅이 로드되었는지 확인합니다.
7. 원본이 변경되면 등록본을 갱신하고 활성화 상태를 다시 확인합니다.

저장소의 `.agents/hooks/`는 배포용 위치입니다. 체크아웃하거나 문서를 읽는 것만으로 훅이 활성화되지 않습니다. 공유 원본은 이동하지 않습니다. 루트 `.codex/`·`.claude/`에는 필요한 자료만 개발자별로 복사·등록할 수 있으며, 해당 로컬 등록본은 Git에서 제외합니다. AGENTS.md 로딩을 위한 대체 지침 파일·심볼릭 링크·추가 로딩 훅도 만들지 않습니다.

이 문서 수정은 저장소 밖의 개인 설정·파일을 변경하는 작업을 포함하지 않습니다. 별도 스킬·Python·셸 파일을 추가하지 않습니다. 호환성 조정에 원본 변경이 필요하면 설정 등록과 구분하여 해당 변경 범위에서 처리합니다.

## 확인 결과

등록 위치·적용 범위·입출력 호환성·신뢰 검토·실제 세션 로딩 여부를 각각 보고합니다. 확인하지 못한 항목은 미확인으로 남깁니다. [오프라인 검사](pr-screenshot-runtime.md#오프라인-검사) 성공을 실제 활성화의 증거로 사용하지 않습니다.
