# PR 스크린샷 코멘트 훅

PR 생성 직후 사용 중인 에이전트가 UI 영향을 판단하고, 필요한 경우 사용자 승인 후 스크린샷 CI를 실행하는 공통 절차입니다. PR 생성 작업과 훅 설정·진단 작업에 적용합니다.

훅 원본은 [`.agents/hooks/pr-screenshot/pr-screenshot.json`](pr-screenshot.json)입니다. 훅이 없거나 PR 생성을 감지하지 못해도 에이전트는 아래 판단·승인 절차를 직접 적용합니다.

## 선행작업

- 루트 [AGENTS.md](../../../AGENTS.md)와 [문서 목록](../../../docs/index.md)을 읽습니다.
- 훅을 설정하거나 활성화할 때는 [훅 설정 레퍼런스](references/pr-screenshot-setup.md)를 읽습니다. 사용 중인 에이전트의 공식 훅 설정 지침으로 지원 여부·입출력 호환성·등록 위치·활성화 방법을 확인합니다.
- 훅을 수정하거나 감지 실패를 진단할 때는 [동작·검사 레퍼런스](references/pr-screenshot-runtime.md)를 읽습니다.
- CI 실행 전에는 [스크린샷 CI 가이드](../../../docs/ci/screenshot-test.md#수동-실행과-에이전트-승인)에서 `develop` 반영 여부·`gh` 로그인·저장소 쓰기 권한을 확인합니다.

## 사용자 확인 기준

- 실제 PR diff와 `scripts/screenshot/scenarios.json` 및 해당 시나리오 코드를 확인해 UI 영향과 커버 범위를 판단합니다. 화면·컴포넌트·리소스·문구·테마·공통 UI·렌더링 의존성 변경을 포함하며, feature 경로가 없다는 이유만으로 생략하지 않습니다.
- UI 영향이 있거나 불확실하면 **PR 생성 후, 실행 전에** PR 링크·전체 head/base SHA·판단 근거·Android/iOS 검사 범위·커버되지 않는 화면을 제시하고 사용자에게 스크린샷 테스트와 결과 댓글 생성 여부를 반드시 묻습니다.
- 명확한 비 UI 변경은 실행을 생략하고 이유를 보고합니다. 예: PR #168처럼 `kmp-spm` 버전만 변경. 버전 카탈로그 전체를 비 UI로 분류하지 않습니다.
- PR 생성 승인은 스크린샷 실행 승인이 아니며, 미응답은 승인으로 취급하지 않습니다. 해당 PR의 스크린샷 실행을 이미 명시적으로 요청받았다면 중복 확인하지 않습니다. 승인받은 head/base가 바뀌면 변경 근거를 설명하고 재확인합니다.
- 고정 상태 렌더링은 ViewModel/API 검증을 대신하지 않습니다. 미포함 화면은 `coverage_gap`으로 알리고, 실행 승인만으로 신규 시나리오를 작성하지 않습니다.

## 실행과 결과 보고

승인 후 `gh workflow run screenshot-pr.yml --repo whatever-x/Caro-Mobile --ref develop`에 PR 번호·승인받은 head/base SHA·고유 요청 ID를 전달합니다. 요청 ID로 실행을 식별하고 비교·이미지 업로드·PR 댓글·Slack 결과를 각각 성공/실패/생략으로 확인합니다. 실행이 바로 조회되지 않아도 자동 재실행하지 않습니다. 명령과 결과 조회 절차는 [스크린샷 테스트](../../../docs/ci/screenshot-test.md#수동-실행과-에이전트-승인)를 따릅니다.

## 가드레일

이 절차의 가드레일은 에이전트가 따르는 행동 규칙입니다. 훅은 사용자 승인을 증명하거나 GitHub 실행을 강제로 차단하는 장치가 아닙니다.

| 조건 | 에이전트가 지킬 규칙 |
| --- | --- |
| 공통 지침이 자동으로 로드되지 않음 | 사용 중인 에이전트의 공식 지침 로딩 방법을 확인합니다. 루트 AGENTS.md와 이 문서를 직접 읽고 적용합니다. |
| 훅 미등록·비활성화·호환성 미확인 | 자동 감지를 전제로 작업하지 않습니다. [설정 레퍼런스](references/pr-screenshot-setup.md)로 확인하고 판단·승인 절차는 직접 적용합니다. |
| PR 생성 후 훅 안내가 없음 | 승인되었다고 판단하지 않습니다. [동작·검사 레퍼런스](references/pr-screenshot-runtime.md)로 감지 범위를 확인합니다. |
| GitHub 웹·API·래퍼·다른 PR 생성 도구 사용 | 현재 훅의 감지를 보장하지 않습니다. 실제 PR을 확인하고 판단·승인 절차를 직접 적용합니다. |
| UI 영향이 불확실하거나 시나리오에 화면이 없음 | 검사 필요성·커버 한계를 알립니다. 임의로 실행하거나 신규 시나리오를 작성하지 않습니다. |
| 미응답 또는 승인받은 head/base 변경 | 실행하지 않습니다. 사용자 확인 기준에 따라 명시적 승인 또는 재확인을 받습니다. |
| CI 실행이 조회되지 않거나 비교 실패 | 자동 재실행하지 않습니다. 요청 ID와 실행 로그로 상태를 확인하고 실패·미확인 상태를 보고합니다. |
| 비교는 끝났지만 댓글이 없음 | 별도 `Screenshot Comment` 실행을 확인합니다. 무변경이면 새 댓글을 만들지 않으며, PR 변경·종료·fork이면 게시를 생략할 수 있습니다. [CI 가이드](../../../docs/ci/screenshot-test.md)를 확인합니다. |
| 오프라인 검사만 통과 | 실제 에이전트의 훅 활성화·질문 또는 CI·댓글·Slack까지 성공했다고 보고하지 않습니다. |

## 참고 자료

본문에는 판단·승인·실행 경계만 두고, 설정과 구현 상세는 필요한 경우에만 읽습니다. 레퍼런스가 자동으로 로드된다고 가정하지 않습니다.
