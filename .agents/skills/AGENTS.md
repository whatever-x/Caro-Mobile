# 에이전트 스킬 관리 지침

`.agents/skills/`의 스킬을 선택·설치하거나 작성·수정할 때 적용합니다.

## 설치 방법

1. 사용 중인 에이전트의 공식 지침에서 스킬 지원 조건·발견 경로·설치 위치·호출 방식을 확인합니다.
2. 자동 발견을 지원하면 공유 원본을 직접 사용합니다. 지원하지 않으면 원본 `SKILL.md`를 직접 읽거나 프로젝트 로컬·사용자 영역에 설치합니다.
3. 설치에는 기존 [Skills CLI](https://github.com/vercel-labs/skills)를 사용합니다. Node.js와 `npx`, 비공개 저장소의 Git 접근 권한을 확인합니다.
4. 스킬 간 상대 참조가 있으므로 전체 묶음을 기본으로 설치합니다. 일부만 설치할 때는 참조하는 형제 스킬도 함께 설치합니다.
5. 설치 후 실제 에이전트 세션에서 스킬 목록과 로딩 여부를 확인합니다.
6. 복사 설치본은 공유 원본이 변경되면 다시 설치해 갱신합니다.

프로젝트 로컬 설치는 공식 지침에서 경로를 확인합니다.
개발자별 로컬 설정·설치본은 Git 공유 대상에서 제외합니다.

## 스킬 선택 및 사용

1. [스킬 탐색 목록](index.md)에서 사용자 요청과 일치하는 스킬을 찾습니다.
2. 해당 `SKILL.md`의 YAML `name`·`description`으로 목적과 적용 조건을 확인합니다.
3. 선택한 스킬의 절차와 작업에 필요한 참고 문서를 읽습니다.
4. 여러 주제가 겹치면 필요한 스킬을 함께 적용합니다.
5. 루트 프로젝트 지침과 선택한 스킬에 따라 작업합니다. 승인·커밋 범위는 사용자 요청을 따릅니다.

## 스킬 문서 작성 규칙

- 폴더 이름과 `SKILL.md`의 YAML `name`을 일치시킵니다. 이름에는 영문 소문자·숫자·하이픈을 사용합니다.
- YAML `name`·`description`은 필수입니다. `description`에는 목적과 적용 조건을 명시합니다.
- `SKILL.md`에는 핵심 작업 절차와 제약을 작성합니다. 상세 문서는 필요한 작업과 읽을 조건을 명시해 연결합니다.
- 사용자용 소개·설치 안내는 `README.md`에 둡니다. 에이전트 작업 규칙은 이 지침과 각 패키지의 `SKILL.md`에서 관리합니다.
- 참고 문서·예제·스크립트는 스킬 디렉토리를 기준으로 상대 경로를 연결합니다. 명령에는 실행 위치와 스크립트 경로를 명시합니다.
- 스킬을 추가·이름 변경·삭제하면 [스킬 탐색 목록](index.md)과 관련 참조를 갱신합니다.
- 외부 스킬의 출처·라이선스 표기를 보존합니다.
- 변경 후 YAML·링크·앵커·스크립트 경로를 확인합니다. 실행 스크립트를 변경하면 관련 검사를 실행합니다.

아래는 현재 패키지 구성을 바탕으로 한 구조 예시입니다.
보조 디렉토리는 필요한 경우에만 둡니다.

```text
skills/
├── README.md                 # 사용자용 소개·설치 안내
├── AGENTS.md                 # 스킬 관리 지침
├── index.md                  # 작업별 스킬 탐색 목록
└── <skill-name>/
    ├── SKILL.md              # 필수: 메타데이터·핵심 작업 절차
    ├── reference/            # 선택: 상세 참고 문서
    ├── examples/             # 선택: 사용·적용 예제
    └── scripts/              # 선택: 실행 스크립트
```

## 가드레일

- 파일이 저장소에 있다는 이유로 자동 발견·로딩·호환성을 가정하지 않습니다.
- 공유 원본을 에이전트별 설치 디렉토리로 이동하지 않습니다.
- 설치본을 별도의 공유 원본으로 관리하거나 에이전트별로 스킬 절차를 중복 작성하지 않습니다.
- 저장소 수정만 요청받은 경우 개인 전역 설치를 실행하지 않습니다.
- 이 묶음은 Caro-Mobile의 KMP·Compose·모듈 구성을 전제로 합니다. 다른 프로젝트에 그대로 적용하지 않습니다.
- Android 전용 스킬은 KMP·iOS 지원 범위와 달라 이 묶음에 추가하지 않습니다.
- 개인 설정·자격증명은 공유 원본이나 설치·배포 패키지에 포함하지 않습니다. 로컬 시험 설치에는 자격증명이 없는 깨끗한 체크아웃을 사용합니다.
- 별도 설치 스크립트나 npm 프로젝트 의존성은 추가하지 않습니다.
- 파일 검사나 설치 명령의 성공만으로 실제 에이전트에서 스킬이 로드·실행되었다고 보고하지 않습니다.
